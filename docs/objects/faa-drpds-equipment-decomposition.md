# FAA DRPDS — equipment decomposition and diagnostic dependency register

**Status:** source-backed decomposition proposal; not an as-built equipment inventory.  
**Parent model:** `examples/objects/faa-drpds.generic.json`  
**Primary description:** `docs/objects/faa-drpds-technical-description.md`

## 1. Purpose and modeling rule

The generic graph currently contains 29 component records and intentionally groups several equipment families. This register decomposes those groups into diagnostic entities without pretending that a historical FAA reference architecture identifies the installed equipment at a particular facility.

Three levels are kept separate:

1. **Family node** — the existing group in the generic graph.
2. **Equipment role** — a functional role supported by the source (for example UPS 2 / Critical Bus A).
3. **Installed instance** — a physical device with site tag, manufacturer, model, ratings, terminals and wiring. These details require current site-specific drawings and equipment records.

Only levels 1 and 2 are described here. Level 3 remains unresolved until site evidence is available. No new physical IDs, cable paths, terminal numbers, ratings, or measurement limits are asserted.

### Count and configuration cautions

- The historical description distinguishes a general typical arrangement from the Honolulu Combined Facility (HCF) exception. Counts must therefore be stored with a configuration qualifier, not as universal constants.
- The source does not establish installed serial numbers, site tags, manufacturer/model for every unit, exact protective-device ratings, conductor sizes, or physical locations.
- A family count is not a wiring relationship. For example, knowing that there are PDUs and SATS does not identify which individual PDU output feeds which SATS input.
- The current graph's `ESS-SWBD` and `UPS-SWGR` nodes are functional aggregations, not proof of one physical enclosure each.

## 3. Diagnostic dependency register

These are prerequisite relationships for diagnosis, not fault-causality assertions. A dependency means that a downstream conclusion cannot be made reliably without checking or accounting for the upstream condition.

| Diagnostic question | Required evidence / upstream dependencies | Distinguishing observations | What cannot be concluded from one observation |
|---|---|---|---|
| Are the two documented commercial sources independent at the facility supply boundary? | Identity of U1/U2; current site one-line or utility records for upstream origins; shared upstream dependencies where documented | Separate upstream origins supported, shared upstream dependency documented, or independence unverified | U1/U2 labels, separate transformers or separate SWGR sections alone do not prove upstream utility independence |
| Is a commercial source unavailable? | Source-boundary identity; source-side measurement quality/freshness; sensing-channel validity; independent/local source-side confirmation where available | Physical source condition versus instrument, sensing-fuse or telemetry failure | A zero PMCS value or downstream transformer/SWGR state alone does not prove loss of the utility source |
| Is each commercial transformer providing supported input/output evidence? | Prior commercial-source assessment; transformer input/output evidence; documented protection/condition indication; measurement quality; corresponding 1M1/2M1 context | Source condition separated from transformer input/output discrepancy, sensing-channel fault and unconfirmed incomer state | Do not infer primary voltage, ratings, impedance, protection implementation or physical test points from the typical reference |
| Is each commercial transformer providing supported input/output evidence? | Source identity; transformer input and output evidence; documented protection/condition indication; measurement quality; corresponding 1M1/2M1 context | Input/output comparison, sensing-channel validity and independent/local evidence | Do not infer primary voltage, ratings, impedance, protection implementation or physical test points from the typical reference |
| Did SWGR transfer to standby? (umbrella) | Commercial source; generator bus readiness; control power; control mode; transfer permissives; breaker actuation/feedback | End-to-end event evidence from authority/mode through permissives, command, position and independent electrical state | A CLOSE command or displayed breaker status alone does not prove closed primary contacts |
| Is SWGR control authority and mode consistent with transfer? | Breaker identity; AUTO/LOCAL/MANUAL selector; active PMCS/local authority; controller availability | Selector state, command origin, controller/PMCS availability and event history | Do not presume AUTO or infer authority from a screen label alone |
| Are source, tie and interlock permissives satisfied? | Both relevant source states; standby incomer permissives; tie state; documented mutual interlocks; event-time context | Permissive/interlock states at command time and source availability | Do not invent permissive equations, timer values or source-paralleling logic |
| Did the breaker execute the command and provide trustworthy feedback? | Command and timestamp; control power; actuator response; auxiliary position feedback; independent electrical state | Command/response comparison, position feedback quality and independent section/path state | Auxiliary contact or PMCS status alone does not prove primary-contact condition |
| Is generator capacity available? | Per-generator start/run/ready state; voltage/frequency; output breaker; common bus; load-shed state | Individual unit alarms and electrical output, bus conditions, number of available units, load state | A running engine alone does not establish an electrically available generator |
| Is the essential switchboard feeder available? | Relevant SWGR section; identified essential switchboard and feeder; feeder protective device | Switchboard input/output, feeder protective state and downstream supply evidence | Switchboard input present does not prove every outgoing feeder is available; a stopped load alone does not prove feeder failure |
| Is the MCC protective and control path available? | Essential feeder; identified MCC/motor feeder; protective device, starter/contactor and documented control/interlock state | MCC supply, trip/alarm, starter/contactor and local/remote control evidence | A stopped motor alone does not prove an MCC fault; do not infer feeder tags or control logic |
| Is the assigned essential load responding as expected? | Proven supply and MCC/control path; documented load identity; local load/motor state and available fault/restart evidence | Load operating state, local alarms, restart inhibit or equipment protection where documented | Do not infer a local load fault until upstream supply and control path are assessed; do not invent restart timers |
| Did essential-load shedding/restoration correspond to generator capacity? | Generator capacity at event time; documented affected feeder/load group; site load-priority and shed/restore criteria | Generator availability, event timestamps, feeder/load state before and after capacity change | Historical generator counts do not establish site thresholds or priority; load absence alone does not prove automatic shedding |
| Is an essential load unavailable because of its supply path? (umbrella) | Essential switchboard feeder, MCC protective/control path and assigned load response | Combined localization across upstream supply, feeder, MCC/control and local load | A downstream stopped motor alone does not identify the failed layer |
| Can an individual generator start and reach run/ready? | Generator identity and start context; starting battery/system; fuel, lubrication, temperature/cooling; controller and alarms | Start/run/ready state, auxiliary-system evidence, controller/alarm state | A start command or cranking alone does not prove a generator is ready |
| Has the running generator reached acceptable electrical output? | Individual generator identity and run/ready state; voltage/frequency; measurement-channel validity | Unit output voltage and frequency with timestamp/quality and independent confirmation where available | Engine running or aggregate bus status does not prove each unit has acceptable output |
| Has the generator synchronized with and connected to the common bus? | Individual unit output; common-bus state; synchronization evidence; output-breaker command and position | Synchronization state, breaker feedback, independent electrical confirmation of connection | A close command or run/ready indication does not prove connection to the bus |
| Is the connected generator fleet sufficient for the documented load? | Connected/available unit count; current load demand; capacity/reserve and load-shed criteria | Bus capacity evidence, load shed/restore state and event context | Historical typical generator count is not a universal site capacity threshold |
| Is generator capacity electrically available? (umbrella) | Start/readiness, electrical output, synchronization/connection and fleet capacity/load-response assessments | Combined unit and bus evidence, available capacity and load-shed/restore context | Do not infer capacity from engine-running state or typical unit counts alone |
| Is the UPS SWGR incoming supply path available? | Documented upstream SWGR section and site-identified UPS SWGR incomer(s) | Upstream section state, incoming protective/switching state, incoming supply indication and measurement quality | Do not assume the number, identity or source pairing of UPS SWGR incomers from the generic architecture |
| Is the UPS SWGR outgoing feeder supplying its assigned UPS input? | UPS SWGR bus/section; site-identified outgoing feeder and assigned UPS input | Feeder protective/breaker state, feeder output and UPS input evidence | UPS SWGR bus voltage does not prove every feeder is available; no individual feeder-to-UPS map is implied |
| Are the UPS rectifier and inverter conversion functions available? | Identified UPS input supply; rectifier and inverter states; output measurements; alarms and event history | Rectifier state, inverter state, output quality and operating mode | Output voltage alone, especially while on bypass, does not prove inverter supply |
| Is the documented UPS bypass function and selected supply path available? | Identified UPS and documented bypass path; mode/selection; bypass source and switching evidence; output continuity | Bypass selection, source/path state, switching feedback and event history | Output present does not prove inverter supply; UPS 1's historical reserve role does not prove installed bypass topology |
| Is the UPS DC bus and battery subsystem able to support the documented operating requirement? | DC bus; battery condition and test results; charger evidence where present; documented string/cell evidence where available | DC bus quality, battery tests/condition, charger alarms and event history | Output voltage or state-of-charge indication alone does not establish required battery autonomy |
| Is a UPS maintaining the critical path? | UPS SWGR incoming supply; documented outgoing feeder; input; rectifier/inverter; bypass; DC bus/battery; output and output SWBD | Combined input, conversion, bypass, battery/DC and output evidence | UPS output voltage alone does not prove inverter operation or battery autonomy; keep UPS battery evidence separate from 125 V DC control power |
| Is the incoming supply to an individual PDU available? | Identified PDU; documented upstream Critical Bus A/B assignment; incoming connection and protective device where documented | Input supply state, measurement quality/timestamp and independent confirmation where available | Group-level PDU status does not prove each input; no individual bus assignment is inferred |
| Is the documented PDU voltage-conversion function available? | Identified PDU; corresponding input and output measurements; documented conversion status/alarms | Input/output voltage evidence, phase/reference identity and conversion alarms | Historical 480/277 V to 208/120 V values are not installed-site ratings; do not infer conversion technology |
| Are the documented PDU internal switching and protective functions available? | Identified PDU; documented internal switching/protective-device schedule; switching feedback, trip/alarm/event evidence where available | Device identity/state, command/feedback agreement, event timestamp and feedback quality | Assess switching only where documented; keep outgoing-feeder protection separate; do not infer topology, settings, selectivity or ZSI |
| Is the documented PDU input, conversion and internal protection available? (umbrella) | Incoming supply, voltage-conversion and main/internal protection assessments | Combined input, conversion and protective-device evidence | A downstream load loss does not localize the PDU internal failure layer |
| Is a documented PDU outgoing feeder available to supply its assigned SATS input? | Identified PDU; individual outgoing feeder and protective device; documented SATS input assignment | Feeder output, protective-device state and corresponding SATS input | The historical statement that each PDU feeds two SATS is not an individual feeder map |
| Is Critical Bus A/B available? | Assigned UPS output path; output switchboard breaker; bus state; measurement-channel validity | Bus voltage/status, upstream UPS mode and breaker state, independent indication | A PMCS bus indication alone does not prove physical bus condition |
| Is the identified SATS sensing and automatic-transfer control function ready? | Identified SATS; both input sensing states; documented AUTO/mode state; controller/control-power readiness where documented; alarms and decision events | Source sensing validity, operating mode, controller readiness, disagreement and event evidence | AUTO indication alone does not prove transfer; no sensing thresholds, logic equations or control-power topology are inferred |
| Is the documented SATS solid-state source-switching function available and responding to control? | Documented transfer command/request; switching-element state/feedback where exposed; both inputs; switching events; output continuity and quality | Command/feedback agreement, switching event, selected source and actual output behavior | No semiconductor count, SCR topology, commutation circuit, overlap behavior or transfer-time limit is inferred |
| Did the SATS respond to a documented loss of one source by transferring to the other? | Both inputs at event time; control readiness; command and switching feedback/event; selected source before/after; output continuity | Actual event response and output quality, with timestamped evidence | A ready controller or selected-source indication alone does not prove completed transfer |
| Is SATS supplying the load from the intended source? | Both SATS input qualities; source-selection logic; transfer state; output path; upstream PDU/bus states | Both input measurements, selected-source indication, transfer events, output measurement | SATS output present does not establish that both redundant inputs are healthy |
| Is the SATS-to-CDP incoming path available? | Individual CDP identity and documented SATS output assignment; SATS output; CDP incomer; incoming protective device where documented | SATS output and CDP incomer states, measurement quality, current one-line assignment | Aggregate SATS-to-CDP relationship does not identify an installed panel or incomer assignment |
| Is a CDP outgoing branch available? | Individual CDP and branch identity; branch protective device; documented critical-load assignment; downstream evidence | Protective-device state, branch/load-side evidence, local load state | A live CDP incomer does not prove every outgoing branch is available; a dead load alone does not localize the fault |

| Did the documented SWGR protective function detect the condition and produce the expected trip response? | Identified protective device and event boundary; documented sensing/pickup, trip output, trip circuit, breaker response and electrical interruption; ZSI evidence only when installed | Event-time measured condition, protective operation, trip output, breaker position and independent electrical state | No relay elements, thresholds, timer values, trip-circuit topology or ZSI wiring are inferred |

## 5. Rules for promoting a role into the electrical graph

A role may become an individual graph component only when all applicable conditions are met:

1. Its existence is explicitly supported by an identified source.
2. The source distinguishes it as an individual item or a distinct functional node.
3. Its source reference resolves to a page/figure/text passage.
4. Any unknown tag, count, rating or connection remains null/unknown.
5. Connections are added only when the source establishes both endpoints and the relationship.
6. A count from a typical architecture is stored as a qualified variant, not copied into a site inventory.
7. A logical observation template is not converted into a physical terminal or measurement point without site drawings and an approved procedure.

## 6. Explicit open items

- Obtain current site-specific one-line diagrams and equipment schedules before creating installed instances.
- Obtain UPS, PDU, SATS and CDP schedules to resolve individual equipment mapping.
- Obtain generator lineup and switchgear control/interlock drawings.
- Obtain PMCS I/O list, network architecture and point database to split combined control/monitoring edges.
- Obtain DC control-power schematic and battery/charger schedule.
- Obtain protective-device coordination/settings documents before modeling trip curves, selectivity or ZSI behavior.
- Confirm current applicable FAA policy and site-approved maintenance procedures before defining field measurement methods.

## 7. Source boundary

This register derives equipment roles and functional dependencies from the repository's FAA DRPDS technical description and its cited historical FAA JO 6480.22 figures/paragraphs. The historical order is cancelled and is used as a detailed architecture reference only. The register does not claim that its example counts, device allocation, or operating logic describe a current named facility. Current policy context is recorded separately in the technical description.

No electrical ratings, live measurements, terminal references, protective settings, or field switching instructions are introduced by this register.
