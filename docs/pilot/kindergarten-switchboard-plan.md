# Пилот: распределительный щит детского сада

## Исходный объект

По данным пользователя:
- назначение: детский сад;
- питание: трёхфазное;
- напряжение: 380/220 В;
- частота: 50 Гц;
- система заземления: TN-C-S;
- год установки: 2026.

На предоставленной схеме указаны два ввода, АВР, контакторы KM1/KM2 по 200 А, трансформаторы тока TA1–TA3 100/5, счётчик «Меркурий 230 AR 5(60)», шины L1/L2/L3/N/PE и отходящие группы.

Итоги схемы: установленная мощность 223,21 кВт, расчётная мощность 115,64 кВт, расчётный ток 176 А.

## Уже выявленные неоднозначности

1. Таблица содержит 11 заполненных групп (1–11), тогда как на схеме визуально прослеживаются групповые аппараты QF1–QF10.
2. Для группы 5 (4,09 кВт; 3,18 А) видно ответвление к обозначению, прочитанному предварительно как ЩОЧ / чердачное помещение; отдельный аппарат защиты не установлен однозначно.
3. Маркировка QF9 читается предположительно как 3C80; QF10 также требует проверки по оригиналу.
4. Список кодов оборудования, предоставленный пользователем, пока не сопоставлен однозначно с позициями схемы.
5. Колонка 12 присутствует, но не заполнена.

Эти пункты нельзя разрешать догадками. Нужен исходный PDF или векторный проект только для уточнения чтения, если он доступен; повторная анкета электрику не требуется.

## План

### P0 — закрепить исходные данные
- сохранить исходную схему в репозитории, если разрешено её публичное размещение;
- зафиксировать пользовательские сведения;
- сохранить текущую предварительную JSON-модель;
- сохранить список неопределённостей.

### P1 — повысить точность разбора
- проверить маркировки и подписи на исходном изображении;
- сформировать перечень компонентов с координатами/областями источника;
- построить граф связей;
- явно пометить сомнительные соединения и номиналы.

### P2 — проверить модель
- автоматические проверки сумм мощностей и токов;
- проверка ссылочной целостности компонентов и линий;
- проверка, что каждая отходящая линия имеет определённый статус защитного аппарата (известен / неизвестен / неоднозначен);
- не трактовать проектную схему как подтверждённую исполнительную.

### P3 — виртуальные сценарии
Подготовить без вмешательства в действующий объект:
- срабатывание групповой защиты;
- перегрев аппарата или соединения;
- отклонение параметров электроснабжения.

Для каждого сценария определить гипотезы, данные, требуемые проверки, доступные приборы, safety constraints и критерии достаточности модели.

### P4 — интеграция
Проверить возможность передачи модели в существующее ядро через имеющиеся контракты MeasurementRequest, MeasurementResult, InstrumentAdapter, SafetyGateway и Session. Не создавать параллельный диагностический движок.

## Критерии пилота

- точность распознавания компонентов и атрибутов;
- точность восстановления электрических связей;
- доля неизвестных, корректно оставленных неизвестными;
- время от загрузки схемы до предварительной модели;
- число и обоснованность дополнительных вопросов;
- способность ядра определить достаточность модели для конкретной проверки;
- корректность блокировки небезопасных действий;
- полезность диагностического плана и заключения для электрика.

## Ограничения

На действующем щите детского сада не создавать неисправности и не выполнять экспериментальные опасные проверки. Первые сценарии — цифровые/виртуальные. Реальные измерения использовать только из имеющихся документов либо из штатной работы квалифицированного специалиста.
