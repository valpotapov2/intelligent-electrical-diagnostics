# Интеграция диагностического ядра

## Что подключено

`src/edi_ingest/diagnostic_core.py` — тонкий мост к реальному приватному репозиторию
`leverty93/diagnostics-mvp`. Он загружает `diag.module`, строит `diag.model`, создаёт
`diag.engine.Session` и проводит каждый запрос через `diag.safety.SafetyGateway`.

Поток выполнения:

1. Ядро выбирает проверку через `Session.step()`.
2. Мост формирует контрактный `MeasurementRequest`.
3. Только `SafetyGateway.measure()` вызывает адаптер.
4. Ответ шлюза передаётся в `Session.add_reply()`.
5. Сохраняются решения, апостериорные вероятности, принятые и отклонённые измерения и журнал шлюза.

Адаптер получает только запрос измерения. Скрытое состояние сценария остаётся внутри виртуального стенда.

## Шесть сценариев KSW

`benchmarks/kindergarten-switchboard/diagnostic-core-module.synthetic.yaml` — отдельный
контрактный модуль для виртуальных тестов. Его точки, уровни 0–5.5 V, прибор и показания
полностью синтетические. Это не модель физических точек ВРУ и не разрешение на измерения
реального щита. Логические fault loci ссылаются на рёбра графа только как синтетические
режимы; они не объявлены физическими компонентами.

Интеграционные тесты проверяют реальные решения ядра для:

- `KSW-BASE-001` — Healthy;
- `KSW-QF4-OPEN-001` — общий виртуальный обрыв;
- `KSW-QF4-BRANCH-001` — виртуальный обрыв ответвления;
- `KSW-QF9-OBS-001` — виртуальная аномалия;
- `KSW-INSTRUMENT-INVALID-001` — отказ адаптера: невалидный результат не становится измерением и ядро не повторяет его автоматически;
- `KSW-UNKNOWN-TOPOLOGY-001` — неизвестная точка АВР блокируется шлюзом до вызова адаптера.

Таким образом, первые четыре сценария проверяют изменение posterior настоящего ядра, пятый —
обработку невалидного результата, шестой — реальную блокировку неизвестной точки. Все измерения
виртуальные; физическая модель ВРУ не расширяется догадками.

## Локальный запуск

```bash
git clone https://github.com/leverty93/diagnostics-mvp.git ../diagnostics-mvp
git -C ../diagnostics-mvp checkout 048587b527342f4dc178e8c99e115c974113fbed
python -m pip install -r ../diagnostics-mvp/requirements.txt
DIAGNOSTICS_MVP_PATH=../diagnostics-mvp pytest -q tests/test_diagnostic_core_bridge.py tests/test_kindergarten_core_scenarios.py
```

В CI нужен repository secret `DIAGNOSTICS_MVP_TOKEN` с read-доступом к приватному репозиторию.
