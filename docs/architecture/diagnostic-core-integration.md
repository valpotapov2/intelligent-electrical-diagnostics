# Интеграция диагностического ядра

## Что подключено

`src/edi_ingest/diagnostic_core.py` — тонкий мост к реальному репозиторию
`leverty93/diagnostics-mvp`. Он не копирует и не имитирует ядро. По заданному
checkout загружает `diag.module`, строит `diag.model`, создаёт
`diag.engine.Session` и проводит каждый запрос через `diag.safety.SafetyGateway`.

Поток выполнения:

1. Ядро выбирает проверку через `Session.step()`.
2. Мост формирует контрактный `MeasurementRequest`.
3. Только `SafetyGateway.measure()` вызывает адаптер.
4. Ответ шлюза передаётся в `Session.add_reply()`.
5. В результате сохраняются решения, апостериорные вероятности, принятые и отклонённые измерения и журнал шлюза.

Адаптер получает только запрос измерения. Скрытое состояние сценария должно оставаться внутри виртуального стенда.
Нельзя передавать неисправность в `Session` или использовать её при выборе следующей проверки.

Интеграция проверена по контрактам commit:

`048587b527342f4dc178e8c99e115c974113fbed`

Для воспроизводимого запуска используйте checkout именно этого SHA. В CI приватный репозиторий

Локальный запуск интеграционного smoke-теста:

```bash
git clone https://github.com/leverty93/diagnostics-mvp.git ../diagnostics-mvp
git -C ../diagnostics-mvp checkout 048587b527342f4dc178e8c99e115c974113fbed
python -m pip install -r ../diagnostics-mvp/requirements.txt
DIAGNOSTICS_MVP_PATH=../diagnostics-mvp pytest -q tests/test_diagnostic_core_bridge.py
```

## Граница текущего этапа

Smoke-тест запускает настоящее ядро на его низковольтном демонстрационном модуле
`power_supply_7805` и синтетическом адаптере исправного стенда. Это проверяет реальный
контракт интеграции, включая SafetyGateway, но не является диагностикой щита детского сада.

Шесть сценариев `KSW-*` пока остаются графовыми сценариями PR #21. Для перевода их в
исполняемые сценарии ядра нужно сформировать отдельный виртуальный диагностический модуль:
- измерительные точки и узлы, имеющие только синтетический смысл;
- fault modes для общего обрыва, обрыва ответвления и аномалии QF9;
- синтетические диапазоны показаний и основания для их различимости;
- безопасные виртуальные профили приборов и декларации шлюза.

Ни один из этих параметров нельзя выводить из одной топологии или подменять
расчётными токами из таблицы нагрузок. Поэтому этот PR подключает настоящие API ядра
и проверяет их рабочий цикл, но не объявляет шесть сценариев уже переведёнными
на физическую модель. SafetyGateway для реального ВРУ не ослабляется: отсутствие
документированных точек, уровней и процедур должно приводить к блокировке.
