# Интеграция с diagnostics-mvp

## Зафиксированная версия

Используется приватный репозиторий `leverty93/diagnostics-mvp`, commit
`048587b527342f4dc178e8c99e115c974113fbed`, контракт модуля 1.3.
GitHub Actions получает его отдельным checkout. Токен доступа хранится только
в секрете репозитория `DIAGNOSTICS_MVP_TOKEN`, в исходники не попадает.

## Что выполняется через реальное ядро

`src/edi_ingest/diagnostic_core.py` использует API ядра, тот же, что и
`harness/runner.py` в diagnostics-mvp:

1. `diag.module.load` — проверка контракта предметного модуля.
2. `diag.model.build` — построение вероятностной модели.
3. `diag.engine.Session.step()` — выбор проверки ядром.
4. `diag.safety.SafetyGateway.measure()` — проверка безопасности и вызов адаптера.
5. `Session.add_reply()` — приём только результата с отметкой SafetyGateway.
6. Проверка апостериорных вероятностей и конечного решения.

Адаптер получает только `MeasurementRequest`. Скрытое состояние сценария
остаётся внутри тестового адаптера и ядру не передаётся.

## Граница достоверности

Исходные материалы щита содержат топологию и проектные сведения, но не
содержат проверенных диапазонов реальных измерений, требований к точности
приборов или эмпирических априорных вероятностей неисправностей. Поэтому
`kindergarten-simulation.module.yaml` — исключительно тестовая фикстура:

- `sim-code` со значениями 0 и 1 — условные числовые коды состояний. Это не
  вольты, омы, токи, измерения непрерывности или физические наблюдения.
- Равномерные веса и значение ошибки подключения 0.5 — тестовые параметры,
  не статистика и не оценка вероятностей для объекта.
- Узлы SafetyGateway являются виртуальными. Адаптер не имеет физического
  интерфейса; `qualified=True` действует только внутри offline-теста.
- KSW-INSTRUMENT-INVALID-001 проверяется инъекцией ошибки прибора с null.
  Ядро не должно принять её как свидетельство.
- KSW-UNKNOWN-TOPOLOGY-001 не превращается в выдуманную неисправность АВР.
  Тест лишает ядро доступного прибора и проверяет остановку без запроса замера.

Эта фикстура не предназначена для диагностики реального щита или допуска к
работам. Для полевого модуля нужны подтверждённые электрические измерения,
процедуры испытаний, профили приборов, данные безопасности и проверенные
априорные вероятности.

## Локальный запуск

Поместить приватный репозиторий в `.deps/diagnostics-mvp` на зафиксированном
commit, затем выполнить:

```bash
python -m pip install -r .deps/diagnostics-mvp/requirements.txt
python -m pip install -e ".[dev]"
DIAGNOSTICS_CORE_PATH=.deps/diagnostics-mvp pytest -q tests/integration
```
